# SGD selects initialization-dependent representations

Experiment code for **SGD Selects Initialization-Dependent Representation in Overparameterized ReLU Networks**. This repository contains the final Section 6 / Appendices H–I experiments, the saved results used in the paper, and generators for Figures 2–5 and Tables 1–5.

There are two separate workflows:

- **Rebuild the paper displays:** use the included `reference_results/`; no training is required.
- **Rerun the experiments:** generate synthetic datasets and train from initialization; new outputs go to `results/` and do not overwrite the reference results.

## Setup

Python 3.12 is recommended. The release was checked in a fresh Python environment on macOS ARM64 using CPU execution. A GPU is not required.

```bash
git clone https://github.com/NikosTsikouras/sgd-initialization-selection.git
cd sgd-initialization-selection
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-tested.txt
```

On Windows, activate with `.venv\Scripts\activate` instead. `requirements-tested.txt` records the environment used to check this release; it is not a reconstructed environment lock for the earlier archived runs. `requirements.txt` lists the direct experiment dependencies, and `requirements-checks.txt` also includes the PDF inspection dependency.

## Rebuild every final figure and table

Run these commands from the repository root:

```bash
python scripts/make_figures.py
python scripts/make_tables.py
python scripts/verify_tables.py --tables-dir paper/tables
```

The figures are vector PDFs in `paper/figures/`:

- Figure 2a: `figure2a_fixed_dataset.pdf`
- Figure 2b: `figure2b_fixed_dataset.pdf`
- Figure 3: `figure3_fixed_dataset.pdf`
- Figure 4: `appendix_scale_rate.pdf`
- Figure 5: `appendix_noise.pdf`

The table generator writes LaTeX, CSV, and JSON versions in `paper/tables/`, including a combined `tables.json`. The verification command compares all 68 rows and 400 numeric entries against an independent snapshot of the final paper's tables, and checks that the JSON display cells agree with the LaTeX. The expected snapshot is in `validation/expected_tables.json`.

To generate a subset of figures or use a different output folder:

```bash
python scripts/make_figures.py --figures 2,3 --output build/main_figures
python scripts/make_figures.py --figures 4,5 --output build/appendix_figures
python scripts/make_tables.py --output build/tables
```

Both display generators accept `--data-dir`. They use only that directory and fail if required inputs are missing; they never silently fill missing fresh results with archived values.

## Check the training implementation

```bash
python scripts/run_experiments.py --dry-run
python scripts/smoke_test.py --include-initialization
```

The smoke test checks simultaneous updates of both layers against an independent one-step calculation, finite-difference gradients, exact Gaussian loss against Monte Carlo, class-share normalization, nonlinear teacher labels, and small training runs. The initialization portion executes all 17 internal variants with two runs each for 20 updates. These small runs are implementation checks, not the paper's experimental results.

See `validation/README.md` for the checks actually completed for this release and their scope.

## Rerun all paper experiments

```bash
python scripts/run_experiments.py --groups all --output results
python scripts/make_figures.py --data-dir results --output build/rerun_figures
python scripts/make_tables.py --data-dir results --output build/rerun_tables
```

All training data are synthetic and generated by the scripts. No external dataset download is needed. The full suite includes long anisotropic controls of up to four million updates per condition; it is substantially more expensive than rebuilding the saved displays or running the smoke test.

The initialization sweep uses CPU execution and 20 runs per condition by default. `--device cuda` explicitly switches that sweep to CUDA, but can change random-number generation and floating-point results. NumPy experiments remain on the CPU. Numerical variation across dependency versions and platforms is possible; the supplied reference results preserve the numbers printed in the paper.

## Model and measurement conventions

The bias-free student is `f(x) = sum_j a_j ReLU(w_j^T x) / sqrt(m)`. Both layers are updated simultaneously from the old parameter values. Fixed-data SGD draws one example uniformly with replacement from a dataset generated once per run, with no regularization.

- Gaussian population losses are computed in closed form. Non-Gaussian and nonlinear-teacher losses use independent test examples as specified by their scripts.
- A fit is the first monitored loss at most `1e-6`; alignment uses maximum angle at most `0.05` radians. Monitoring intervals are part of each experiment's configuration.
- Figure 2's “end of alignment” marker denotes the first monitored threshold crossing at step 3,540. Small later fluctuations occur; alignment remains below the threshold at all monitored iterates from step 4,340 through fitting at step 6,440.
- Most allocation errors pool absolute log-share errors across neurons and fitted runs. Table 2 instead uses medians of within-run means; its daggered cases use the retained-neuron diagnostic defined in the caption. Figure 5 uses medians of within-run median errors at fixed checkpoints. Table 5 uses final checkpoints because the nonlinear teachers are not exactly representable.
- The proper Xavier-normal control has hidden-entry variance `2/(d+m)` and effective output-weight variance `2/(m+1)`. Its 20 independent seeds differ from the archived initialization sweep.

The initialization implementation retains all 17 internal conditions, including an older condition named `Xavier-style`, because removing conditions would change the shared random-number sequence. That legacy condition is excluded from the final table and replaced by the separate proper Xavier-normal control. The two small core/nonlinear libraries remain separate because their teacher and loss implementations differ.

## Repository layout and provenance

```text
experiments/        Training implementations and summary generation
scripts/            Experiment launcher, smoke checks, final display generators
reference_results/  Saved paper results; see its README for checkpoint availability
paper/figures/      Rebuilt final vector figures
paper/tables/       Rebuilt final tables in LaTeX, CSV, and JSON
validation/         Independent expected table values and release checks
results/            Newly trained results (created on demand; ignored by Git)
build/              Alternative generated displays (ignored by Git)
```

Each experiment fixes its random seeds in code. The launcher records the selected groups and Python version in `results/run_configuration.json`. Most original additional-experiment archives preserved summaries rather than every raw checkpoint; the corresponding runners regenerate those checkpoints. Original summaries are kept separate from release-time reruns and are never silently replaced.
